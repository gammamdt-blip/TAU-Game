# Changelog

## 1.0.0 - TAU: THE CITY IS WATCHING.

The game that started as **Rooftop Run** (a pixel-art, 480 × 160, standalone HTML5 endless runner based on
the MIT-licensed `canabalt-hf` rules) was transformed in place into **TAU**. The simulation was ported
rule for rule; everything the player sees and hears was rebuilt.

### Gameplay: preserved

Verified against the original running side by side (see [Testing](#testing)):

* Auto-run, variable-height jump, gravity, terminal fall speed, the four-step acceleration ramp up to
  800 units/s, drag, stumbling and the 30 % speed loss on kicking an obstacle.
* The collision system (swept AABB with the same overlap tolerance), including walls, floors, ceilings
  in corridors and moving floors (crumbling buildings).
* The procedural generator: two leapfrogging buildings, speed-driven gaps, widths, climbs and drops, the
  fixed first two buildings, the schedule and survivability rules for special buildings (security corridors,
  crumbling buildings, missile roofs, crane decks), obstacle and drone chances.
* Hazards: debris obstacles, corridor glass, drones, crumbling roofs, the dropping missile, the fatal
  fall below the world.
* Distance counter (metres = units / 10), best distance, game over, restart, pause, mute, fullscreen,
  keyboard / mouse / touch / gamepad input, saved best distance (the old `rr_best` record and `rr_muted`
  flag are migrated).

### Added

**Visual identity**

* Modern, cinematic, ~95 % monochrome dystopian look: charcoal, concrete, steel, blue-grey and fog white;
  the only colour is a faint cold blue and warning-red / dim-white light accents.
* Four parallax skyline layers (atmospheric, far, mid, near) of dense megacity towers, bridges, antennas,
  billboards (including the giant surveillance display), stacks and cranes; a generated sky; three drifting
  fog banks; a haze gradient.
* Two giant walking mechs between the far and mid layers (idle, walk, fire and vent smoke), an airship, an
  occasional gunship with a raking searchlight, patrolling background drones with blinking red lights,
  and foreground columns and trusses that whip past.
* Rain in two depth layers that leans back with speed, rain splashes and wet-roof reflections, steam from
  vents, dust, rubble, sparks, shock rings, glass shards, film grain, vignette, additive blinking warning
  lights, a cold halo that keeps the dark runner readable, camera shake and a white flash.
* Rooftop set dressing: antennas, vents, pipes, tanks, crates, skylights, access huts, CCTV poles,
  surveillance towers, floodlights, railings, fences, fire escapes, in three roof styles; panelled
  corridors with strip lights and doors.
* The runner is a small dark human silhouette with a backpack and a 48-frame skeleton-driven animation set:
  run (four speeds), jump, fall, tumble, landing and death.
* Perched drones replace the doves; the crane, missile and crumbling-building art were redrawn.

**Rendering**

* A resolution-independent renderer (details in [docs/GAME_SYSTEMS.md](docs/GAME_SYSTEMS.md#8-rendering)):
  logical view of 270 units tall, width following the window aspect ratio between 1.2 and 2.4 (letterboxed
  beyond), canvas backing store sized from the window, the device pixel ratio, a resolution setting and an
  adaptive scale, capped at 3840 × 2160.
* Artwork authored at 8 pixels per unit (native on a 4K screen) with a lazily built mip chain, so it is
  always minified, never blurred up; camera snapped to device pixels; buildings drawn from tiled
  textures every frame instead of pre-rendered bitmaps.
* Quality presets (low / medium / high) and individual switches for rain, fog, reflections, grain and
  vignette; optional adaptive resolution; FPS readout.

**Interface**

* Minimal surveillance-terminal HTML interface over the canvas (crisp at any resolution): main menu
  (TAU / THE CITY IS WATCHING. / START RUN / SETTINGS / CREDITS), HUD (distance, speed bar, tracking dot,
  pause / mute / fullscreen icons, control hint), pause screen, game-over screen
  (TAU / RUN TERMINATED / DISTANCE: 00000m / TRY AGAIN, with the cause of death and best distance),
  credits with the licence notices.
* Settings (Graphics, Audio, Gameplay tabs) saved in `localStorage` and applied immediately; reset to
  defaults; full keyboard and gamepad menu navigation.
* Inter typeface (Light, Regular, Medium), bundled.

**Audio**

* The mixer architecture is kept (master plus effects / music / ambience / rain buses), now with volume
  sliders in Settings, corridor muffling and a speed-dependent ambience swell.
* All 37 sounds were rebuilt as an industrial, wet, mechanical soundscape: footsteps on concrete and metal,
  jumps, landings, impacts, glass, collapse, missile, gunship fly-by, drone lift-off, and looping
  ambience, rain and music. They are generated by code and shipped as local files.

**Project**

* Compact structure: `index.html`, `style.css`, `config.js`, `assets.js`, `game.js` (16 labelled sections,
  JSDoc comments), `assets/`, `tools/generate-assets.py`, `docs/`.
* `config.js` holds every tunable number; `assets.js` holds every file name; both are documented in place.
* Documentation: README (16 topics), CUSTOMIZATION, PROJECT_STRUCTURE, GAME_SYSTEMS, ASSET_GUIDE, LICENSE.
* `tools/generate-assets.py` rebuilds all images and sounds reproducibly.

### Changed

* Pixel-art sprites drawn to a 480 × 160 canvas and scaled with `image-rendering: pixelated` → smooth,
  high-resolution rendering through a units-to-pixels transform.
* Pre-rendered building bitmaps → display lists replayed every frame at the current resolution.
* Pixel font and canvas-drawn menus → HTML interface.
* Gameplay and cosmetic randomness are now separate generators, so no visual setting can change how a run
  plays.
* The simulation is sub-stepped to at most 20 ms per step, so it behaves identically at any frame rate.
* Game identity, tagline and game-over wording come from `config.js`.
* The offline launch method is unchanged in spirit: all code is classic `<script>` files and the sounds
  are also embedded as `audio-data.js`, so opening `index.html` straight from disk works without a server.

### Removed

* All Rooftop Run artwork, sounds, wording and branding. Every shipped asset is referenced by the game.
* The pixel font.

### Fixed during development

Problems found by the tests and corrected before delivery:

* **`file://` launch threw about 60 errors.** Reading a skyline's edge colour from the picture is refused
  by browsers for images opened from disk. The colour is now stored in the manifest (`edge`) with a safe
  fallback.
* README and CUSTOMIZATION figures that did not match measurements (image counts, frame positions,
  jump heights, performance numbers) were re-measured and corrected.
* Configuration values that nothing used (a duplicate per-preset step limit and a light-blink range) were
  removed, and the game name, tagline and game-over title now really are read from `config.js`.

### Not verified

These could not be checked here and should be considered **unverified**:

* **Real-hardware frame rate (the 60 fps target).** The test machine has no GPU. With software rendering the
  loop ran at about 32 fps at 1280 × 720 and 17 fps at 1920 × 1080, and the adaptive resolution reacted as
  designed. One physics step costs about 0.02 ms; drawing cost scales with pixel count.
* **Physical gamepads and real touchscreens**: the Gamepad API was mocked and touch input was injected.
* **Firefox and Safari**: only Chromium was available.
* **Real 4K display output**: 3840 × 2160 canvases were created and drawn, but not viewed on a 4K panel.

## Known limitations

* The distant backdrop (skylines at 1.5-4 pixels per unit, fog banks, mechs, airship, gunship and the
  foreground silhouettes) is authored below the 8 px/unit native density of a 4K screen and is magnified
  there. It always sits behind haze or fog. Everything the player stands on and touches is at native density.
* On portrait phones the aspect ratio is clamped to 1.2-2.4 and the rest is letterboxed; play in landscape.
* Audio starts after the first click or key press (a browser rule, not a bug).
* Generated artwork and sound are good, consistent placeholders for a larger production: hand-made art and
  recordings can replace any file (see [docs/ASSET_GUIDE.md](docs/ASSET_GUIDE.md)).
