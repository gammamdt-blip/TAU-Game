# TAU — THE CITY IS WATCHING.

TAU is an offline, one-button endless runner. You are a small figure on the rooftops of a vast, fogbound,
surveilled megacity. The run never ends; it only gets faster, until you fall, hit a wall, or the sky
falls on you.

It is written in plain JavaScript and HTML5 Canvas: no libraries, no build step, no server, no network
requests. All art and sound are original, generated by a script included in the project.

TAU is the existing standalone game "Rooftop Run" (a port of the `canabalt-hf` Canabalt rules) transformed
in place. The gameplay rules were kept exactly (see
[How the gameplay was preserved](#how-the-gameplay-was-preserved)); the look, the renderer, the interface,
the sound and the code organisation are new.

---

## 1. What TAU is

* **Gameplay:** auto-run, one button. Tap to hop, hold to jump higher. Speed climbs from 100 to 800 units/s.
  Cross gaps, kick through debris, smash corridor windows, ride crumbling buildings, outrun missile strikes,
  and survive the cranes. Your score is the distance in metres. Your best distance is saved.
* **Look:** modern, cinematic, almost monochrome: charcoal, concrete, steel and fog, with warning-red and
  dim-white lights as the only accents. Parallax skyline layers, drifting fog banks, rain, wet-roof
  reflections, drones, a gunship with a searchlight, airships, colossal walking machines in the haze,
  giant surveillance billboards, film grain and a vignette.
* **Rendering:** the picture is drawn at your screen's real resolution (including 4K and high-DPI
  screens), not scaled up from a small bitmap. Physics never depends on resolution.

## 2. How to launch it locally

**Easiest: double-click `index.html`.** It opens in your default browser and plays, with sound, with no
server. (Tested in headless Chromium, both from `file://` and over `http://`. Firefox, Safari and
real-GPU frame rates were not tested; see [Known limitations](#tested-and-known-limitations).)

Optional: serve the folder instead (this also works):

```
cd TAU
python3 -m http.server 8000
# then open http://localhost:8000
```

Why no server is needed: the scripts are classic `<script>` tags (not ES modules, which browsers refuse to
load from `file://`), and the sounds are also embedded as `assets/audio/audio-data.js`, which the game loads
when `fetch` of local files is blocked.

**Controls**

| Action | Keyboard | Mouse / touch | Gamepad |
|---|---|---|---|
| Jump (hold for higher) | `X` `Z` `C` `Space` `Enter` `Tab` `W` `↑` | press and hold on the picture | A / B / X |
| Start / restart / resume | `X` `Z` `C` | click the buttons | A on a button, Start to pause |
| Pause | `P` or `Esc` | pause icon (top-left) | Start |
| Mute | `M` | speaker icon | n/a |
| Fullscreen | `F` | fullscreen icon | n/a |
| Menu navigation | `↑` `↓` `Enter` `Esc` | click | D-pad / left stick, A, B |

Everything is also reachable by mouse or touch alone.

## 4. What each major file does

| File | Role |
|---|---|
| `index.html` | Static markup for every screen (menu, pause, game over, settings, credits, HUD). Loads three scripts in order: `config.js`, `assets.js`, `game.js`. |
| `config.js` | One `CONFIG` object. Edit numbers here to re-balance or re-style the game. Loaded first. |
| `assets.js` | `ASSETS` (the manifest of every file the game uses) and `Assets` (loading, mip chain, tiled patterns, audio bytes). No other file mentions a file name. |
| `game.js` | Everything else: settings and save data, display scaling, sound mixer, input, runner and physics, hazards, procedural level generation, parallax background and weather, rendering, interface logic, main loop. Sections are marked with `// ====` banners and numbered (the list is at the top of the file). |
| `style.css` | Look of the HTML interface. Sizes are in `em`; `game.js` sets the base font size from the picture height so the interface scales with the picture. |
| `tools/generate-assets.py` | Python (Pillow, NumPy, SciPy). Draws all the artwork and synthesises all the sound with fixed random seeds, so the output is reproducible. You never need it just to play. |

See [`docs/PROJECT_STRUCTURE.md`](docs/PROJECT_STRUCTURE.md) for more detail.

## 5. Where the important configuration values are

All in **`config.js`**, grouped under headed sections:

| Section | Controls |
|---|---|
| `physics.runner`, `physics.speedRamp`, `physics.jump`, `physics.landing` | speed, acceleration, gravity, jump strength and hold time, stumble thresholds |
| `world`, `generator` | building sizes, gaps, drops, corridor heights, how often special buildings appear, obstacle and drone chances |
| `hazards` | obstacle kick, collapse speed, missile trigger distance and fall speed, glass shards |
| `camera`, `view` | framing, look-ahead, visible area and aspect-ratio limits |
| `background` | skyline layers, fog banks, haze, walking machines, airship, gunship, drones, foreground silhouettes |
| `weather` | rain amount, speed, length, wind, splashes, steam |
| `graphics` | quality presets, resolution scales, grain and vignette strength, light blink rates |
| `audio` | mix levels |
| `ui`, `defaults` | restart delay, distance formatting, default settings |

## 6. How to replace the player artwork

The runner is one sprite sheet, `assets/images/player.png`: **1536 × 1152 px, 8 columns × 6 rows of
192 × 192 px frames** (24 × 24 game units at 8 px per unit), 48 frames in this order:

| Frames | Animation |
|---|---|
| 0–15 | run cycle |
| 16–19 | jump |
| 20–26 | fall |
| 27–37 | tumble (stumble) |
| 38–41 | soft landing |
| 42–47 | death |

Alignment rule: the hit box is 12 × 14 units at offset (4, 10) inside the 24 × 24 frame, so **the
character's feet must touch the bottom edge of the frame**, horizontally centred, with the body
inside the middle 12 units. Transparent PNG. Save over the file (or change `file:` in `assets.js`). Full
procedure: [CUSTOMIZATION.md](CUSTOMIZATION.md#changing-the-players-appearance) and
[docs/ASSET_GUIDE.md](docs/ASSET_GUIDE.md).

## 7. How to replace buildings and backgrounds

* **Building walls and roof surfaces** are tileable textures: `wall_slit`, `wall_grid`, `wall_panel`,
  `wall_rib` (walls), `roof_a`, `roof_b`, `roof_c` (roof strips), `floor_plate`, `floor_grate`, `hall_wall`
  (corridors). Replace a PNG with the same name and size and every building that uses it changes.
* **Rooftop clutter** (antennas, vents, pipes, tanks, crates, fences, skylights, access huts, cameras,
  floodlights): one PNG each, drawn standing on the roof.
* **Backdrop:** `sky.jpg`, four skyline layers (`skyline_atmos`, `skyline_far`, `skyline_mid`,
  `skyline_near`), `fog_bank`, plus `mech_walker`, `airship`, `gunship`, `drone`, `fg_column`, `fg_truss`.
* Where each layer sits and how fast it scrolls is in `config.js` → `background`.

The `ppu` value in `assets.js` is the number of source pixels per game unit for that file. If you change a
file's resolution, change its `ppu` to match.

## 8. How to change colours and lighting

* Most colours live in the artwork. Edit the palette near the top of `tools/generate-assets.py` and run
  `python3 tools/generate-assets.py images`, or repaint the PNGs by hand.
* Runtime colour and light: `background.haze` (colour of the haze gradient), `background.fog[].alpha`,
  `graphics.vignetteStrength`, `graphics.grainAlpha`, and the light colours in `Light.sprite()` in
  `game.js` (section 12).
* Warning lights are listed per image under `lights:` in `assets.js` as `[x, y, 'red' | 'white']`.

## 9. How to adjust fog, rain and visual effects

* **Fog:** `background.fog` is a list of three banks; raise or lower each `alpha` (0 to 1). `drift` is its
  own sideways speed, `scale` its size. Switch fog off or on in Settings, or set `fogLayers` per quality
  preset in `graphics.presets`.
* **Rain:** `weather.rainCount`, `rainSpeed`, `rainLength`, `rainWind`, `rainAlpha`, `splashesPerSecond`.
* **Other effects:** `graphics.grainAlpha`, `graphics.vignetteStrength`, `weather.steamChance`,
  `background.gunship` (flyby frequency, speed, searchlight), `hazards.glass.shards`.
* In game, Settings → Graphics has switches for rain, fog, wet reflections, film grain and vignette, and a
  quality preset.

## 10. How to modify running speed and jumping physics

`config.js` → `physics`. The values are the original game's; the game is balanced around them.

* Speed: `runner.startSpeed`, `runner.maxSpeed`, and the acceleration table `speedRamp`.
* Jump: `jump.maxHold` and `jump.speedDivisor` set how long the button keeps lifting you; `runner.maxFall`
  also sets the take-off speed; `runner.gravity` pulls you back.

Measured results are in [CUSTOMIZATION.md](CUSTOMIZATION.md#changing-jump-height).

## 11. How to change difficulty

* Gaps: `generator.minGapFraction` (higher = always long gaps), `gapScale`.
* Drops: `generator.maxDropTiles` (smaller = flatter city), `maxJumpTiles`.
* Hazards: `generator.obstacleChance`, `roofObstacleChance`, `specialEvery`, `firstSpecial` (how soon and how
  often corridors, crumbling roofs, missile strikes and cranes appear).
* Pace: `physics.speedRamp`, `physics.runner.maxSpeed`; penalties: `physics.obstacleSlow`,
  `physics.landing.stumbleFallTime`.

## 12. How to add new obstacles

An obstacle is the `Obstacle` class in `game.js` (section 9): an ankle-high box that the runner kicks, which
slows the runner to 70 % of its speed. To add a variant:

1. Draw a 4-frame sheet (frames 14 × 14 units) and add it to `ASSETS.images` in `assets.js`
   (`fw: 14, fh: 14, cols: 4`).
2. In `Obstacle`'s constructor, choose your image (it already switches between `obstacles` and `obstacles2`).
3. Where obstacles are placed (search for `new Obstacle` in the builder, section 10), add your variant or
   change `generator.obstacleChance`.

For an entirely new hazard type, copy the pattern of `Drone` or `GlassWindow`: a class with
`update(dt, G)` and `draw()`, held in an array on `Sequence` (`this.drones`, `this.windows`...), updated in
`Sequence.update` and drawn in `Sequence.draw`.

## 13. How to add new environmental objects

Rooftop props are drawn from a display list. In section 10 (`Sequence.prototype.decorate`) props are placed
with `DL.prop('name', x, groundY)`. To add one:

1. Add the PNG (drawn at 8 px per unit; standing on its bottom edge) to `assets/images/`.
2. Register it in `ASSETS.images`, with any blinking `lights: [[x, y, 'red']]`.
3. Call `DL.prop('your_prop', x, y)` inside `decorate` (or add it to a list such as `ANTENNAS`).

Props are decorative; they have no collision. Solid things are `blocks` (see
[docs/GAME_SYSTEMS.md](docs/GAME_SYSTEMS.md)).

## 14. How to modify the interface

* Markup: `index.html`. Each screen is a `<section class="screen">`; the HUD is `#hud`.
* Look: `style.css` (colours are variables at the top).
* Behaviour: `game.js` section 15 (`UI`). Settings controls are generic: any `<input>` or `<select>` with
  `data-setting="group.name"` is bound to the saved setting of that name. Add a new default under
  `defaults` in `config.js` and a control with a matching `data-setting`.
* Menu wording (`TAU`, the tagline, `RUN TERMINATED`, the version shown in Credits) is in `config.js` → `game`;
  the Credits text and the page `<title>` are in `index.html`.

## 15. How to add new audio

1. Put a mono or stereo `.wav` into `assets/audio/` (any sample rate; 44.1 kHz recommended).
2. Add its id (file name without `.wav`) to `ASSETS.audio` in `assets.js`.
3. Play it with `Snd.play('id', volume, rate)` where it should happen.
4. Rebuild the `file://` bundle: `python3 tools/generate-assets.py bundle`. (Not needed if you only use
   `http://`.)

Ambience, rain and music are looping buses; footsteps, impacts and interface sounds go through the effects
bus. All obey Settings → Audio and the mute key.

## 16. How to troubleshoot common problems

| Problem | Try |
|---|---|
| Blank page / stuck on LOADING | Open the browser console (F12). A missing file in `assets/` is reported by name. Make sure the folder structure is intact. |
| No sound | Browsers start audio only after a click or key press; press START RUN. Check M (mute) and Settings → Audio. Over `file://` the sound comes from `assets/audio/audio-data.js`: it must be present. |
| Choppy frame rate | Settings → Graphics: lower QUALITY, set RENDER RESOLUTION to 75 % or 50 %, turn off wet reflections / fog. "Adaptive resolution" (on by default) already lowers the resolution automatically when the frame rate drops. Make sure browser hardware acceleration is on. |
| Soft or blurry picture | RENDER RESOLUTION must be 100 %; check browser zoom is 100 %. |
| Settings or best distance lost | They are stored in the browser's `localStorage` for this page; private windows and "clear site data" erase them. Keys: `tau_settings`, `tau_best`. |
| Edited `config.js` and nothing changed | Hard-refresh (Ctrl/Cmd+Shift+R). A typo in `config.js` shows up as an error in the console. |
| Regenerated art looks different from the manifest | The `ppu` in `assets.js` must match the generator's pixels-per-unit for that image. |

## How the gameplay was preserved

Rewriting the look must not change how the game plays, so this was checked by running the original game
and TAU side by side (see CHANGELOG.md):

* identical runner state, frame by frame, for scripted and random button input on the real opening and on
  a hand-built course with walls, ceilings, gaps and edge landings (80 random scripts, 0 differences);
* an identical speed curve (800 units/s reached after 82.45 s in both);
* the level generator produces the same distribution of gaps, drops, widths and building types as the
  original (40 speed / height / building-type configurations, 1,000 to 6,000 generated buildings each,
  means within sampling noise, which was measured by comparing the original with itself).

## Tested, and known limitations

What was tested, and how, is listed in CHANGELOG.md. In short, it passed an automated run in headless
Chromium covering start-up, menus, keyboard, mouse, touch and (emulated) gamepad input, pause, game over,
restart, best-distance persistence, settings, audio gains, fullscreen, 14 window sizes / pixel ratios /
aspect ratios up to 4K, and a 15-minute procedural soak run with no errors.

Not verified, because there was no way to:

* **60 fps on real hardware.** The test machine has no GPU (software rendering): the real-time loop ran at
  roughly 32 fps at 1280 × 720 and 17 fps at 1920 × 1080 there, and the adaptive-resolution system did lower
  the internal resolution in response. The simulation itself costs about 0.02 ms per step; drawing is the
  cost and scales with pixel count. Expect much higher rates with GPU-accelerated Canvas.
* **Physical gamepads and touchscreens**, and **Firefox / Safari**: the gamepad API was emulated and touch
  events injected in Chromium.
* **Distant backdrop sharpness at 4K.** The foreground and playable art is authored at 8 pixels per unit,
  which is native resolution on a 3840 × 2160 screen. The far skyline layers, fog, the walking machines and
  the airship are authored at 1.5 to 4 pixels per unit (they sit behind haze and a file at 8 would be
  hundreds of MB), so they are magnified on 4K screens.
* On portrait phones the picture is letterboxed into a landscape-ish window (aspect ratio clamped to
  1.2 to 2.4); landscape is recommended.
