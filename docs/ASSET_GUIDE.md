# TAU - asset guide

Every image, sound and font in `assets/` is listed in **`assets.js`**; nothing else in the code mentions a
file name. All of it is generated by `tools/generate-assets.py`, but you are free to replace any file with
your own artwork or recordings.

## 1. Units and pixel density

The game world is measured in **units** (one tile = 16 units, the runner's hit box = 12 × 14 units, the view
is 270 units tall). Images are stored at some number of **pixels per unit (`ppu`)**. For example, a roof strip
that is 64 × 14 units and stored at 8 ppu is a 512 × 112 pixel file.

The manifest entry gives the density; the game derives the drawn size from it:

```
size in units = file pixels / ppu            (unless fw / fh are given for a sprite sheet)
```

At draw time `Assets.level()` chooses the smallest copy of the image (built by halving) whose density is
still at least the screen's pixels per unit, so art is only ever scaled **down**. A 1080p display needs 4
pixels per unit; a 4K display needs 8. That is why most art is stored at **8 ppu**: it is exactly 1:1 on a
3840 × 2160 screen. Backdrop layers that sit far away are stored at lower densities (see the table) because
they are always seen through fog and haze.

* To make a picture **sharper** without changing how big it appears: draw it with more pixels and raise
  `ppu` in the manifest by the same factor. (A 512 × 512 wall tile at 8 ppu → 1024 × 1024 at 16 ppu.)
* To make a picture **appear bigger or smaller**: change its pixel size at the same `ppu`, or change `ppu`
  at the same pixel size. For props this changes their drawn size; for gameplay-relevant things
  (the runner, obstacles) keep the size, because hit boxes do not follow the picture.

## 2. Formats

| Kind | Format |
|---|---|
| Images | PNG (8-bit RGBA; RGB for the opaque tiles `roof_*`, `floor_*`, `hall_wall`), plus one JPEG: `sky.jpg` (quality 92, no chroma subsampling) |
| Sounds | WAV, **22 050 Hz, mono, 16-bit PCM** (any rate decodable by the browser works; this is what the generator writes) |
| Fonts | OpenType (`.otf`), declared in `ASSETS.fonts` (family `TAU Sans`) |
| Audio bundle | `assets/audio/audio-data.js`: the same WAV files as base64, used when the game is opened from disk |

Colours: the artwork is deliberately close to monochrome (charcoal, concrete, steel, fog white). The only
chroma in the set is a faint cold blue and the warning-red / dim-white light accents, which are drawn by the
game as additive glow (`lights` in the manifest), not baked into the pictures.

## 3. Replacing an image

1. Make your picture **the same size** as the file it replaces (or follow the rules for its class below).
2. Save it over the file in `assets/images/` with the **same name**. If you prefer another name, put it in
   `file:` in `assets.js`.
3. If you changed its pixel density, update `ppu` in `assets.js`.
4. Reload the page (hard reload, Ctrl+F5, if your browser cached the old file).

Rules by class (the "class" is the group heading in the table below):

| Class | Rules |
|---|---|
| **Backdrop skylines** (`skyline_*`) | Must tile horizontally (left edge continues the right edge): they are drawn twice side by side and wrap. Transparent above the skyline. The colour under the strip comes from `edge` in the manifest: set it to the colour of the strip's bottom row. |
| **`fog_bank`** | Tiles horizontally; semi-transparent wisps. Drawn three times at different scales and opacity (`background.fog` in `config.js`). |
| **`sky.jpg`** | Any size; it is scaled to cover the view (plus an 8 % margin for drift). The shipped file is 1920 × 1080; use 3840 × 2160 if you want it pixel-exact on a 4K screen. |
| **Walls** (`wall_*`) | Seamless in both directions; 64 × 64 units. Tiled with a random horizontal offset per building. |
| **Roof, floor, hall strips** (`roof_*`, `floor_*`, `hall_wall`, `fence`, `railing`, `crane_deck`) | Seamless horizontally; they are repeated along x only. The height is the height of the strip as drawn (roof 14, floor 14, hall wall 32, fence 32, railing 10, crane deck 32 units). |
| **`crane_column`** | Seamless vertically (it repeats down the side of the building). |
| **Rooftop props** | Any size; they stand on the roof line, **bottom-aligned**, with a transparent margin only where you want one. Blinking lights are placed from `lights: [[x, y, 'red'|'white'], ...]`, measured in units from the picture's top-left corner. Re-measure them when the picture changes (the generator prints them). |
| **Sprite sheets** (`player`, `escape`, `obstacles`, `obstacles2`, `doors`, `cracks`, `drone`, `mech_walker`, `smoke`, `gibs`) | A grid of equal frames: `fw` × `fh` units each, `cols` per row. Frame `i` is at column `i % cols`, row `i / cols` (counting from the top left). Frame order matters: the code refers to frame numbers. |
| **`player`** | 8 × 6 frames of 24 × 24 units (192 × 192 px). Feet on the bottom edge of the frame, body inside the middle 12 units, to match the 12 × 14 hit box at offset (4, 10). Frames: 0-15 run, 16-19 jump, 20-26 fall, 27-37 tumble, 38-41 land, 42-47 die. |
| **Interface icons** (`ui_*`, `icon`) | Square PNG, shown at their pixel size scaled by CSS. Flag `native: true`, so they are never mip-mapped. |
| **`grain`** | 256 × 256, seamless, grey noise with alpha. Drawn 1:1 over the whole picture. |

## 5. Audio

All sounds are 22.05 kHz mono 16-bit WAV in `assets/audio/`, listed by id in `ASSETS.audio`. The file for
id `jump1` is `assets/audio/jump1.wav`.

| Event | Ids (duration) |
|---|---|
| Footsteps, roof | `foot1` ... `foot4` (0.14 s each) |
| Footsteps, metal deck / corridor floor | `footc1` ... `footc4` (0.20 s) |
| Jump | `jump1`, `jump2`, `jump3` (0.25, 0.28, 0.31 s). Each jump picks 0-3 at random; 0 is silent |
| Landing, stumble, wall hit, fall | `land` (0.22 s), `tumble` (0.6 s), `wall` (0.6 s), `fall` (1.0 s) |
| Debris kicked | `obstacle1` ... `obstacle3` (0.32 s) |
| Corridor glass | `window1`, `window2` (0.9 s: pane breaks), `glass1`, `glass2` (0.24 s: shards bounce) |
| Collapse | `crumble` (3.4 s) |
| Missile | `bomb_pre` (1.3 s: incoming), `bomb_hit` (1.3 s: lands), `bomb_explode` (2.4 s) |
| Aircraft | `flyby` (2.8 s: gunship) |
| Perched drones lifting off | `drone1` ... `drone3` (0.55 s) |
| Run start | `start` (0.9 s) |
| Interface | `ui_move` (0.06 s), `ui_select` (0.3 s), `ui_back` (0.22 s) |
| **Loops** | `ambience` (16 s: industrial hum, wind, distant machinery), `rain` (8 s), `music` (24 s: slow electronic drone) |

The three loops are played with `loop = true`: **the end must continue into the start** or you will hear a
click. The mixer buses, ducking and corridor muffling are described in
[GAME_SYSTEMS.md](GAME_SYSTEMS.md#10-audio).

### Replacing a sound

1. Export your sound as WAV (mono keeps the file small; stereo works too).
2. Save it over `assets/audio/<id>.wav`.
3. **Rebuild the offline bundle** so the game still has the new sound when opened from disk:
   `python3 tools/generate-assets.py bundle` (needs only Python 3). If you only ever run the game from a web
   server you can skip this step: over http the `.wav` files are loaded directly.
4. Reload. Browsers keep audio locked until the first click or key press: that is normal.

Keep the footsteps and UI sounds short, and normalise levels: the mixer applies the volume settings and the
per-event volumes in `game.js`, not per-file loudness.

### Adding a sound

Add the id to `ASSETS.audio` in `assets.js`, put `<id>.wav` in `assets/audio/`, rebuild the bundle and call
`Snd.play('<id>', volume)` where the event happens in `game.js`. A sound that is missing or fails to decode is skipped
and the game keeps running (over http a missing `.wav` makes the loader fall back to the offline bundle).

## 6. Fonts

The interface uses **Inter** (Light 300, Regular 400, Medium 500) as the family `TAU Sans`, declared in
`ASSETS.fonts` and loaded with the `FontFace` API. Inter is licensed under the SIL Open Font License 1.1;
the licence text is `assets/fonts/OFL.txt`. To change the typeface, put the files in `assets/fonts/`,
change `file` (and, if you like, `family`) in the manifest, and update `--font` in `style.css` if you
change the family name. If a font fails to load the interface falls back to the system sans-serif.

## 7. Adding a new asset

Example: a new rooftop prop `water_tower.png`.

1. Draw it bottom-aligned at 8 px per unit (a 30 × 50 unit tower is 240 × 400 px) and save it in
   `assets/images/`.
2. Add `water_tower: { ppu: 8, lights: [[15, 2, 'red']] }` to `ASSETS.images` in `assets.js`.
3. Use it: add `'water_tower'` to a list in `game.js` or call `DL.prop('water_tower', x, groundY)` inside
   `Sequence.prototype.decorate` (§10). For an antenna-like prop, appending the id to `ANTENNAS` is enough.
4. Reload. A missing image stops start-up with the message "Could not start the game: Could not load
   assets/images/water_tower.png" instead of failing silently.

New building textures work the same way: add an entry and append the id to `WALLS` or `ROOFS`. A new
background layer is a new entry in `config.js → background.layers` with the matching manifest entry
(including its `edge` colour).

## 8. Regenerating with the generator

```
python3 tools/generate-assets.py                      # everything: images, sounds, audio-data.js
python3 tools/generate-assets.py images               # only the artwork
python3 tools/generate-assets.py audio                # only the sounds (and the bundle)
python3 tools/generate-assets.py bundle               # only audio-data.js, from the .wav files present
python3 tools/generate-assets.py images skyline       # only steps whose name contains "skyline"
python3 tools/generate-assets.py audio foot jump      # only sounds whose id contains "foot" or "jump"
```

Requires Python 3 with Pillow, NumPy and SciPy (the game does not). Output is deterministic: running it
twice produces identical files.

Filters are **substring matches against step names**, not file names:

| Mode | Step names you can filter on |
|---|---|
| images | `sky`, `fog_bank`, `skyline` (or `skyline_atmos`, `skyline_far`, `skyline_mid`, `skyline_near`), `wall`, `roof`, `floor`, `hall_wall`, `antenna`, `tower_cctv`, `vent_pipes`, `roofprops`, `fence_railing_escape`, `obstacles_doors_cracks`, `crane`, `player`, `mech`, `airship`, `gunship`, `drone`, `missile`, `smoke`, `gibs`, `fg_`, `ui_icon`, `grain` |
| audio | any sound id, or part of one: `foot`, `jump`, `bomb`, `ui_`, `rain`, `music`, ... |

Note that `wall_rib` (a file name) does **not** match anything; use `wall` to regenerate all four wall
textures. A bare word given without a mode (`python3 tools/generate-assets.py drone`) applies to both
images and sounds. When the generator draws a prop with warning lights it prints their positions, ready to
paste into `lights` in `assets.js`.

The palette and the per-layer settings (skyline heights, window styles, fog, haze, bridges, billboards) are
at the top of the relevant sections of the script, so re-theming the whole game is mostly a matter of
editing numbers and re-running it. If you change a `ppu` in the script, change the same `ppu` in `assets.js`.

## 9. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| The page shows "Could not start the game: Could not load assets/images/x.png" | The file is missing or misnamed; the name in the message is the one the manifest expects. |
| My picture looks blurry | Its `ppu` is lower than the screen needs (4 px/unit at 1080p, 8 at 4K). Draw it at a higher density and raise `ppu` to match. |
| My picture is the wrong size | `ppu` in the manifest does not match the density you drew it at. |
| A sprite sheet shows the wrong frame or half a frame | `fw`, `fh` or `cols` in the manifest does not match the sheet. |
| The runner floats or sinks into the roof | The feet are not on the bottom edge of the 24 × 24 unit frame (see §3). |
| My new sound plays over http but not from disk | The offline bundle is stale: run `python3 tools/generate-assets.py bundle`. |
| The skyline has a visible seam | The strip does not tile: its first and last columns must continue each other. |
| A gap or a different colour under a skyline strip | Set `edge` for that entry to the colour of the strip's bottom row. |
| Changes do not show | The browser cached the old file: hard reload. |
